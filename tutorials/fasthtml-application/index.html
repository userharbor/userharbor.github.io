FastHTML Application with UserHarbor¶

This tutorial builds a Hypermedia-Driven Application (HDA) with FastHTML, HTMX, and UserHarbor. The server returns HTML, and the browser updates the page through HTMX attributes.

What you will build¶

You will create an application with registration, email verification, login, password recovery, a paginated user list, user details, password changes, and account deletion. Only the account owner sees their password and deletion forms. Basecoat provides the UI components.

Start with the finished application

Use FastHTML Starter as a repository template if you want to run the finished application immediately. Its README contains the setup instructions. This walkthrough explains how to build the same account flows, with a smaller dashboard layout.

FastHTML handles routing, form parsing, and HTML rendering. HTMX sends requests and swaps HTML. UserHarbor handles account validation, password hashing, tokens, sessions, and account operations. Your application decides who may access each page.

Install dependencies¶

Use Python 3.14 or later, matching the starter, and uv:

uv init --python 3.14 fasthtml-app
cd fasthtml-app
uv add python-fasthtml "userharbor[sqlalchemy,smtp]" \
  fasthtml-basecoatui "fasthtml-tailwindcss[dev]" \
  fasthtml-lucide

The Python wrappers fasthtml-basecoatui, fasthtml-tailwindcss, and fasthtml-lucide provide UI components, stylesheet generation, and icons. No separate JavaScript application or JSON API is needed for these flows.

Organize the application¶

Use the same separation as the starter:

app/
├── core/             # Settings, UserHarbor instance, shared types
├── components/       # Forms, cards, table, pagination, alerts
│   └── auth/
├── layouts/          # HTML document and page shells
├── pages/            # Components composed into complete pages
├── routes/           # Request parsing and domain calls
├── email_templates/  # Verification and recovery links
├── static/
└── main.py           # Session middleware and mounted applications

Create the directories and package files:

mkdir -p app/core app/components/auth app/layouts app/pages app/routes \
  app/email_templates app/static
touch app/__init__.py app/core/__init__.py app/components/__init__.py \
  app/components/auth/__init__.py app/layouts/__init__.py \
  app/pages/__init__.py app/routes/__init__.py

Save each code block in the file named above it. When a step says to append code, keep the preceding contents of that file. Finish creating the files before starting the application: routes import pages, and pages import their components.

Configure settings and UserHarbor¶

Create .env at the project root. Choose a random secret key and fill in your SMTP credentials. APP_URL is the public base URL used in email links.

.env
SECRET_KEY=replace-with-a-long-random-secret
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-smtp-username
SMTP_PASSWORD=your-smtp-password
SMTP_FROM_EMAIL=noreply@example.com
APP_URL=http://localhost:8000

Keep .env out of version control. The run command at the end loads it into the process environment. Read those settings in app/core/settings.py:

app/core/settings.py
import os

SECRET_KEY = os.environ["SECRET_KEY"]
SMTP_HOST = os.environ["SMTP_HOST"]
SMTP_PORT = int(os.getenv("SMTP_PORT", "587"))
SMTP_USERNAME = os.getenv("SMTP_USERNAME")
SMTP_PASSWORD = os.getenv("SMTP_PASSWORD")
SMTP_FROM_EMAIL = os.environ["SMTP_FROM_EMAIL"]
APP_URL = os.getenv("APP_URL", "http://localhost:8000")

Configure one shared UserHarbor instance. The SQLAlchemy adapter persists accounts and sessions, and the SMTP adapter sends account emails.

The SQLite URL is relative to the working directory, so running from app/ creates app/users.db. create_all() creates the tables on the first run.

app/core/harbor.py
from pathlib import Path

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from userharbor import UserHarbor
from userharbor_smtp import SMTPEmailSender
from userharbor_sqlalchemy import SQLAlchemyUserStore

from .settings import (
    APP_URL,
    SECRET_KEY,
    SMTP_FROM_EMAIL,
    SMTP_HOST,
    SMTP_PASSWORD,
    SMTP_PORT,
    SMTP_USERNAME,
)

engine = create_engine("sqlite:///users.db")
SessionLocal = sessionmaker(bind=engine)

store = SQLAlchemyUserStore(SessionLocal)
store.metadata.create_all(engine)

email_sender = SMTPEmailSender(
    host=SMTP_HOST,
    port=SMTP_PORT,
    username=SMTP_USERNAME,
    password=SMTP_PASSWORD,
    from_email=SMTP_FROM_EMAIL,
    template_dir=Path(__file__).parent.parent / "email_templates",
    template_context={
        "app_url": APP_URL,
    },
)

harbor = UserHarbor(
    secret_key=SECRET_KEY,
    store=store,
    email_sender=email_sender,
)

The custom email directory can override individual templates. Add these two files so verification and recovery messages point to our routes. Other account notifications use the SMTP adapter's default templates.

app/email_templates/verification.html
<p>Hello {{ username }},</p>
<p>
  <a href="{{ app_url.rstrip('/') }}/auth/verify_email?token={{ token | urlencode }}">Activate your account</a>
</p>
app/email_templates/password_reset.html
<p>Hello {{ username }},</p>
<p>
  <a href="{{ app_url.rstrip('/') }}/auth/reset_password?token={{ token | urlencode }}">Reset your password</a>
</p>

Define the return type used by routes. A route can return HTML, a response, or HTML together with HTMX response headers. UserLike describes the public user fields; it does not expose the password hash.

app/core/types.py
from fasthtml.common import FT, HttpHeader, Response
from userharbor.interfaces import UserLike

type HTMLResult = FT | Response | tuple[FT | HttpHeader, ...]
User = UserLike

Build the shared layouts¶

HTML document, assets, and loading indicator¶

Every page uses BaseLayout. It loads HTMX, Basecoat's JavaScript, and the stylesheet generated from Basecoat's nova theme. The Tailwind development integration builds the CSS and watches for class changes while the app runs.

hx_boost="true" lets ordinary internal links navigate through HTMX. They still have real URLs, including pagination query parameters. A boosted link normally replaces the body contents and updates browser history.

The single Spinner has htmx-indicator, which hides it while idle. hx_indicator is inherited from the body, so forms and links use this indicator without repeating its selector. The #alerts container receives feedback from any form.

app/layouts/base.py
from fasthtml.common import (
    FT,
    Body,
    Div,
    Head,
    Html,
    Meta,
    Script,
    Title,
)
from fasthtml_basecoat import (
    BasecoatInput,
    BasecoatJS,
    Spinner,
)
from fasthtml_tailwindcss import TailwindHead


def BaseLayout(*c, title: str, **kwargs) -> FT:
    return Html(
        Head(
            Title(title),
            Meta(charset="utf-8"),
            Meta(name="viewport", content="width=device-width, initial-scale=1"),
            Script(src="https://cdn.jsdelivr.net/npm/htmx.org@2.0.11/dist/htmx.js"),
            BasecoatJS(),
            TailwindHead(input=BasecoatInput("nova"), watch=True),
        ),
        Body(
            Spinner(
                id="global-spinner",
                cls="fixed left-1/2 top-1/2 -translate-x-1/2 -translate-y-1/2 z-50 pointer-events-none size-10 htmx-indicator",
            ),
            Div(
                id="alerts",
                cls="fixed top-4 inset-x-0 z-50 flex flex-col items-center gap-4",
            ),
            *c,
            hx_boost="true",
            hx_indicator="#global-spinner",
        ),
        **kwargs,
    )

Return form feedback as HTML¶

Create a shared Alert component. The outer element uses hx_swap_oob="beforeend:#alerts", so HTMX appends the returned message to the layout's alert container even when a form uses hx_swap="none".

Domain errors can therefore be displayed without replacing the form or erasing the user's input. UserHarborError remains a domain exception; rendering the message is the application's responsibility.

app/components/alert.py
from typing import Literal

from fasthtml.common import FT, H2, Div, Footer, Section
from fasthtml_basecoat import Button
from fasthtml_lucide import Icon


def Alert(heading: str, message: str, variant: Literal["info", "error"]) -> FT:
    return Div(
        Div(
            Icon("info"),
            H2(heading),
            Section(message),
            Footer(
                Button(
                    Icon("circle-x"),
                    aria_label="Close",
                    data_tooltip="Close",
                    data_side="bottom",
                    data_variant="ghost",
                    onclick="this.closest('.alert').remove()",
                ),
            ),
            cls="alert w-full max-w-md",
            data_variant="destructive" if variant == "error" else None,
            hx_on__load="setTimeout(() => { this.remove() }, 10000)",
        ),
        hx_swap_oob="beforeend:#alerts",
    )

Create the authentication forms¶

Login¶

Each input's name matches a route parameter. FastHTML reads the submitted values and passes them to the handler. Basecoat's Input, Label, Button, and Card wrappers produce the HTML and styling.

hx_post sends the form to the handler. hx_swap="none" prevents the ordinary response swap; alerts and explicit response headers control the visible result. The hx_disabled_elt selector disables the form's inputs and buttons during the request. It uses a unique form ID, so another form on the page remains usable.

The recovery link switches the Basecoat tabs to the hidden recovery panel.

app/components/auth/login.py
from fasthtml.common import FT, H2, A, Div, Form, Header, P, Section
from fasthtml_basecoat import (
    Button,
    Card,
    Input,
    Label,
)


def LoginCard(**attrs) -> FT:
    return Card(
        Header(
            H2("Login to your account"),
            P("Enter your credentials to access your account."),
        ),
        Section(_LoginForm()),
        **attrs,
    )


def _LoginForm() -> FT:
    return Form(
        Div(
            Label("Username", fr="username"),
            Input(
                type="text",
                id="username",
                name="username",
                required=True,
            ),
            cls="grid gap-2",
        ),
        Div(
            Div(
                Label("Password", fr="password"),
                A(
                    "Forgot your password?",
                    onclick="event.preventDefault(); this.closest('.tabs').select(document.getElementById('auth-forgot-password-tab'));",
                    cls="ms-auto inline-block text-sm underline-offset-4 hover:underline",
                ),
                cls="flex items-center",
            ),
            Input(
                type="password",
                id="password",
                name="password",
                required=True,
            ),
            cls="grid gap-2",
        ),
        Button("Login", cls="w-full"),
        cls="grid gap-6",
        id="login-form",
        hx_post="login",
        hx_disabled_elt="#login-form input, #login-form button",
        hx_swap="none",
    )

Registration¶

The success response replaces the registration card through HX-Retarget and HX-Reswap. These response headers override the form's default swap behavior. Keep the panel ID and tab attributes on the replacement so Basecoat's tabs can continue to find it.

app/components/auth/register.py
from core.types import HTMLResult
from fasthtml import HttpHeader
from fasthtml.common import FT, H2, Div, Form, Header, P, Section
from fasthtml_basecoat import Button, Card, Input, Label


def RegisterCard(**attrs) -> FT:
    return Card(
        Header(
            H2("Create an account"),
            P("Enter your details to create your account."),
        ),
        Section(_RegisterForm()),
        **attrs,
    )


def SuccessfulRegisterCard() -> HTMLResult:
    return (
        Card(

            role="tabpanel",

        HttpHeader("HX-Reswap", "outerHTML"),

def _RegisterForm() -> FT:
    return Form(
        Div(
            Label("Username", fr="register-username"),
            Input(
                type="text",
                id="register-username",
                name="username",
                autocomplete="username",
                required=True,
            ),
            cls="grid gap-2",
        ),
        Div(
            Label("Email", fr="register-email"),
            Input(
                type="email",
                id="register-email",
                name="email",
                autocomplete="email",
                required=True,
            ),
            cls="grid gap-2",
        ),
        Div(
            Label("Password", fr="register-password"),
            Input(
                type="password",
                id="register-password",
                name="password",
                autocomplete="new-password",
                required=True,
            ),
            cls="grid gap-2",

        Button("Create account", cls="w-full"),

Enter a new password¶

The reset form carries the email token in a hidden input. autocomplete="new-password" tells password managers that these fields contain a new password. The route will also compare the two submitted values.

Connect authentication forms to UserHarbor¶

Create app/routes/auth.py. This is a mounted FastHTML application: its local /login route will be available at /auth/login after we mount it.

Start with the imports, router, and page route:

app/routes/auth.py
from components.alert import Alert
from components.auth.forgot_password import SuccessfulForgotPasswordCard
from components.auth.register import SuccessfulRegisterCard
from components.auth.reset_password import SuccessfulResetPasswordCard
from core.harbor import harbor
from core.types import HTMLResult
from fasthtml.common import FT, HttpHeader, Response, fast_app
from pages.auth import AuthPage
from pages.reset_password import ResetPasswordPage
from pages.verify_email import VerifyEmailPage
from userharbor.exceptions import UserHarborError

auth_app, rt = fast_app()


@rt(methods=["GET"])
def index() -> FT:
    return AuthPage()

Register and verify an account¶

Append these handlers to app/routes/auth.py. Registration calls harbor.register(), which validates the account, hashes the password, stores the verification token hash, and sends the verification email.

The email link opens a GET route with token in the query string. Successful verification activates the account so the user can log in. The page avoids sending the token URL as a referrer and is not cached.

app/routes/auth.py
@rt(methods=["POST"])
def register(username: str, email: str, password: str) -> HTMLResult:
    try:
        harbor.register(username, email, password)
    except UserHarborError as e:
        return Alert("Registration Failed", str(e), variant="error")
    return SuccessfulRegisterCard()


@rt(methods=["GET"])
def verify_email(token: str) -> HTMLResult:
    try:
        harbor.verify_email(token)
    except UserHarborError as e:
        page = VerifyEmailPage(error=str(e))
    else:
        page = VerifyEmailPage()
    return (
        page,
        HttpHeader("Referrer-Policy", "no-referrer"),
        HttpHeader("Cache-Control", "no-store"),
    )

Log in with an HttpOnly session cookie¶

Append the login handler. harbor.login() returns the raw session token; UserHarbor persists its hash. The web application stores the raw token in an HttpOnly cookie, so page scripts do not need to read it.

A successful HTMX login returns HTTP 200 with HX-Redirect, which makes the browser load /. Do not combine this header with a 3xx response: HTMX does not process response headers on 3xx responses.

secure=False is for local HTTP development. Set it to True when deploying behind HTTPS.

app/routes/auth.py
@rt(methods=["POST"])
def login(username: str, password: str) -> HTMLResult:
    try:
        session_token = harbor.login(username, password)
    except UserHarborError as e:
        return Alert("Login Failed", str(e), variant="error")
    response = Response(headers={"HX-Redirect": "/"})
    response.set_cookie(
        "session_token",
        session_token,
        path="/",
        httponly=True,
        secure=False,  # Set to True in production with HTTPS
        samesite="lax",
    )
    return response

Log out¶

Logout should invalidate the server-side session as well as clear the cookie. An already expired session can be treated as logged out. Append:

app/routes/auth.py
@rt(methods=["POST"])
def logout(request) -> HTMLResult:
    try:
        harbor.logout(request.cookies.get("session_token", ""))
    except UserHarborError:
        pass
    response = Response(headers={"HX-Redirect": "/auth/"})
    response.delete_cookie("session_token", path="/")
    return response

Recover a forgotten password¶

Append the recovery handlers. harbor.send_password_reset() sends a token when the address is known and returns neutrally for unknown addresses. The email link opens ResetPasswordPage; its form submits the token and new password.

harbor.reset_password() validates the token and password, changes the password, and invalidates all sessions for that user. The success card sends the user back to login.

app/routes/auth.py
@rt(methods=["POST"])
def forgot_password(email: str) -> HTMLResult:
    try:
        harbor.send_password_reset(email)
    except UserHarborError as e:
        return Alert("Password Reset Failed", str(e), variant="error")
    return SuccessfulForgotPasswordCard()


@rt(methods=["GET"])
def reset_password(token: str) -> HTMLResult:
    return (
        ResetPasswordPage(token),
        HttpHeader("Referrer-Policy", "no-referrer"),
        HttpHeader("Cache-Control", "no-store"),
    )


@rt(methods=["POST"])
def update_password(token: str, new_password: str, confirm_password: str) -> HTMLResult:
    if new_password != confirm_password:
        return Alert(
            "Password Reset Failed", "Passwords do not match.", variant="error"
        )
    try:
        harbor.reset_password(new_password=new_password, reset_token=token)
    except UserHarborError as e:
        return Alert("Password Reset Failed", str(e), variant="error")
    return SuccessfulResetPasswordCard()

List users with query-string pagination¶

Create the table component. Profile links contain URL-encoded usernames; HTML text is escaped by FastHTML.

app/components/user_table.py
from urllib.parse import quote

from fasthtml.common import FT, A, Tbody, Td, Th, Thead, Tr
from fasthtml_basecoat import Table
from userharbor.interfaces import UserList


def UserTable(users: UserList) -> FT:
    return Table(
        Thead(
            Tr(
                Th("Username"),
                Th("Email"),
                Th("Verified"),
            )
        ),
        Tbody(
            *[
                Tr(
                    Td(
                        A(
                            u.username,
                            href=f"/users/{quote(u.username, safe='')}",
                            cls="hover:underline",
                        )
                    ),
                    Td(u.email),
                    Td("Yes" if u.verified else "No"),
                )
                for u in users.items
            ]
        ),
    )

Use the installed Basecoat Pagination and PaginationLink wrappers. Links such as ?page=2 work as normal URLs and inherit boosted navigation from the body. The active page gets aria-current="page" from PaginationLink(current=True).

app/components/pagination.py
from fasthtml.common import FT
from fasthtml_basecoat import Pagination as BasePagination
from fasthtml_basecoat import PaginationLink


def Pagination(page: int, total_pages: int) -> FT | None:
    return (
        BasePagination(
            PaginationLink("Previous", href=f"?page={page - 1}") if page > 1 else None,
            *(
                PaginationLink(
                    str(number), href=f"?page={number}", current=number == page
                )
                for number in range(1, total_pages + 1)
            ),
            PaginationLink("Next", href=f"?page={page + 1}")
            if page < total_pages
            else None,
        )
        if total_pages > 1
        else None
    )

Create the users router. FastHTML parses page: int = 1 from the query string. harbor.users.list() accepts limit and offset, and returns both the items and the total number of matching users. That total determines the page count.

Clamp page numbers to the available range. An empty database still renders the first page with an empty table. The details handler will be added in the next step.

app/routes/users.py
from core.harbor import harbor
from core.types import HTMLResult
from fasthtml.common import HTTPException, fast_app
from pages.user_details import UserDetailsPage
from pages.users import UsersPage

users_app, rt = fast_app()


@rt(methods=["GET"])
def index(request, page: int = 1) -> HTMLResult:
    page_size = 10
    page = max(1, page)
    users = harbor.users.list(limit=page_size, offset=(page - 1) * page_size)
    total_pages = max(1, (users.total + page_size - 1) // page_size)
    if page > total_pages:
        page = total_pages
        users = harbor.users.list(limit=page_size, offset=(page - 1) * page_size)
    return UsersPage(users, request.scope.get("user"), page, total_pages)

Change passwords and delete the signed-in account¶

Create a separate mounted router at /account. These operations take their identity from the session cookie, not from a submitted username or the profile URL. UserHarbor validates the token and current password before changing the account.

On a successful password change, all sessions are invalidated. Both successful operations clear the browser cookie and redirect to login. Errors return the same out-of-band alert used by the authentication forms.

The deletion handler also checks confirmed on the server. Hiding a form or disabling a button alone is not authorization.

app/routes/account.py
from components.alert import Alert
from core.harbor import harbor
from core.types import HTMLResult
from fasthtml.common import Response, fast_app
from userharbor.exceptions import UserHarborError

account_app, rt = fast_app()


@rt(methods=["POST"])
def change_password(
    request, old_password: str, new_password: str, confirm_password: str
) -> HTMLResult:
    if new_password != confirm_password:
        return Alert(
            "Password Change Failed", "Passwords do not match.", variant="error"
        )
    try:
        harbor.change_password(
            old_password=old_password,
            new_password=new_password,
            session_token=request.cookies.get("session_token", ""),
        )
    except UserHarborError as e:
        return Alert("Password Change Failed", str(e), variant="error")
    response = Response(headers={"HX-Redirect": "/auth/"})
    response.delete_cookie("session_token", path="/")
    return response


@rt(methods=["POST"])
def delete(request, password: str, confirmed: bool = False) -> HTMLResult:
    if not confirmed:
        return Alert(
            "Account Deletion Failed",
            "Confirm account deletion first.",
            variant="error",
        )
    try:
        harbor.delete_account(
            password=password,
            session_token=request.cookies.get("session_token", ""),
        )
    except UserHarborError as e:
        return Alert("Account Deletion Failed", str(e), variant="error")
    response = Response(headers={"HX-Redirect": "/auth/"})
    response.delete_cookie("session_token", path="/")
    return response

Protect pages and mount the routers¶

Create app/main.py. The root middleware validates the session before dispatching to any mounted application and puts the current user in request.scope["user"]. A hook on just one child FastHTML application would not protect its siblings.

Authentication pages and static assets remain accessible without a session. Authenticated users are sent away from the login screen, while logout and email verification/recovery links remain available.

Ordinary requests use a 303 redirect. For HTMX requests, the middleware returns HX-Redirect with HTTP 200 so an expired session navigates to the login page instead of inserting it into an existing form or alert target.

app/main.py
from contextlib import suppress

from core.harbor import harbor
from fasthtml.common import FastHTML, Response, StaticImmutable
from routes.account import account_app
from routes.auth import auth_app
from routes.users import users_app
from starlette.middleware import Middleware
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.responses import RedirectResponse
from starlette.routing import Mount
from userharbor.exceptions import UserHarborError


def redirect(request, url: str):
    if request.headers.get("HX-Request") == "true":
        return Response(headers={"HX-Redirect": url})
    return RedirectResponse(url, status_code=303)


async def check_session(request, call_next):
    path = request.url.path
    user = None
    if token := request.cookies.get("session_token"):
        with suppress(UserHarborError):
            user = harbor.get_current_user(token)
    request.scope["user"] = user

    public = path == "/auth" or path.startswith(("/auth/", "/static/"))
    if user and path in ("/auth", "/auth/", "/auth/login", "/auth/register"):
        return redirect(request, "/")
    if not user and not public:
        response = redirect(request, "/auth/")
        response.delete_cookie("session_token", path="/")
        return response
    return await call_next(request)


app = FastHTML(
    middleware=[Middleware(BaseHTTPMiddleware, dispatch=check_session)],
    routes=[
        Mount("/static", StaticImmutable(directory="static"), name="static"),
        Mount("/auth", auth_app, name="auth"),
        Mount("/account", account_app, name="account"),
        Mount("/", users_app, name="index"),
    ],
)

Run the application¶

From the project root, start the application with the environment file:

cd app
uv run --env-file ../.env uvicorn main:app --reload

Open http://localhost:8000. Running from app/ also makes the core, routes, pages, and components imports resolve and places users.db beside main.py.

Try the complete flow:

  1. Register an account and follow the verification link sent by email.
  2. Log in and open your profile from the header or user table.
  3. Create enough accounts to navigate to ?page=2 and back.
  4. View another user's profile: the password and deletion forms are absent.
  5. Change your password and log in again with the new one.
  6. Log out, request a reset email, and set a new password through its link.
  7. On your own profile, confirm deletion and enter your password to remove the account.

While a request is running, the shared spinner appears and that form's controls are disabled. If a domain operation fails, an alert appears without replacing the form. The logout button disables only itself.

How the HTMX pieces fit together¶

Attribute or header Purpose in this application
hx-boost Navigate internal links through HTML requests and update browser history.
hx-post Submit form values to a FastHTML route.
hx-swap="none" Leave the form in place unless the response explicitly replaces it.
hx-swap-oob Append feedback to the shared alerts container.
HX-Retarget and HX-Reswap Replace a card after a successful operation.
HX-Redirect Navigate to a new page after login, logout, or account changes.
hx-disabled-elt Disable selected form controls or the triggering button during a request.
hx-indicator Show the shared loading indicator during a request.

These attributes describe browser behavior directly beside the UI that triggers it. The routes keep returning HTML; UserHarbor remains independent of HTMX and FastHTML. See the HTMX documentation for boosted navigation, disabled controls, and redirect responses.
